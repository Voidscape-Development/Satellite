# Vendored OMT header

`libomt.h` is the C interface to [libomt](https://github.com/openmediatransport/libomt),
copyright © Open Media Transport Contributors and **MIT licensed**, like every other Open
Media Transport repository. Vendoring it here means Satellite builds without anyone having
to obtain the OMT sources first.

Satellite links against nothing in it. The header only describes the ABI; the library itself
is located and loaded at run time by `src/transport/omt/`.

## Rules for this directory

- **Do not edit this file.** It is upstream verbatim. Anything Satellite needs on top of it
  belongs in `src/transport/omt/`.
- `.clang-format` here sets `DisableFormat: true`, because CI passes changed files to
  clang-format explicitly and would otherwise reformat upstream code.

## Where the libraries themselves come from

This is the awkward part, and it is worth writing down so it is not rediscovered.

**Upstream publishes no binaries.** Neither `libomt` nor `libvmx` has a single GitHub
release, and neither repository commits build output — both are source-only:

| Repository | Language | Build requirement |
|---|---|---|
| [`libomt`](https://github.com/openmediatransport/libomt) | C# | **.NET 8 SDK**, compiled with NativeAOT to produce a native library with C exports |
| [`libvmx`](https://github.com/openmediatransport/libvmx) | C / C++ | A C++ compiler; the repo carries per-platform build scripts |

`libomtnet`, the protocol implementation, is statically linked into `libomt` by the NativeAOT
build, so at run time only **`libomt` + `libvmx`** are needed. The .NET requirement is
build-time only — nothing at run time needs a .NET installation.

Prebuilt copies of both do exist inside the release packages of
[`omtplugin`](https://github.com/openmediatransport/omtplugin), the reference OBS plugin,
which is where the impression that upstream ships binaries comes from. Those are that
project's packaging, not a library distribution.

So Satellite has to either build both from source in CI or ship neither. Until that is
settled, the OMT backend reports itself unavailable with the reason shown in the Satellite
window, and everything else keeps working — see `docs/ARCHITECTURE.md` §11.
